# Flow Player（流程播放器）

把"任意沿时间或因果方向推进的离散流程"做成可视化讲解。两种交付：

- **静态图**（轻量交付）：一张手工布局的对照图——左边过程流（时间自上而下），右边被逐步改变的状态/数据结构，箭头 = 谁写谁。
- **播放器**（完整交付）：单文件、可播放、可暂停、可单步的交互页，读者逐跳看清每个单元的完整旅程：在哪产生 → 经由哪里 → 落效到什么。

## 适用判断

适用：存在①**站点集合**（流程经过的"地方"——端点、角色、阶段、状态机状态均可）②**离散单元**（消息、报文、工作项、凭证、控制转移）③每个单元产生**可见的状态变更**。
不适用：连续模拟量；无时间维的纯静态结构（组织树、实体关系等）——那不属于本 skill，别硬套。

## 播放器十条契约（不可协商）

1. **单文件、零依赖**：一个 HTML，双击即开，无外部资源。
2. **逐跳步进**：每个单元至少拆三段「① 产生/发出 → ② 移动 → ③ 落效」。**状态只在③变化**——"①刚发生、状态就变"的瞬移即缺陷。
3. **站点即泳道**，按因果方向从左到右排列；**状态面板嵌在拥有它的泳道内部**（它是该站点的内部状态，不是舞台外的独立区域）。
4. **布局零位移**：舞台固定高度、控制栏置顶且 sticky、增长的内容一律内部滚动。播放全程控制按钮坐标不变——用断言验证，不靠目测。
5. **聚光灯**：当前子步骤所在泳道高亮，其余去饱和；可一键开关。
6. **传输控制**：播放/暂停、单步 ±1、进度条逐段可点、倍速、重置，加键盘绑定。
7. **步骤日志**：每个单元一行、**落效时**追加、当前行高亮。不可观测的机制说明（系统如何知道结束、如何打包）用独立视觉类别，绝不与真实单元混淆。
8. **真实载荷**：单元内容照录来源，可截断、不可改写或虚构；数字与标识符保持原样。
9. **故障注入**：内置"流程中断"演示——在某个中间单元后断开，后续单元灰显为"未到达/未执行"，弹出部分状态面板（完整 / 部分 / 缺失三档，各配恢复或回退路径）。断点用步骤 id 定位，不写死下标。
10. **确定性回放**：任意时刻 seek(i) 从零重建精确状态——每步的 state 幂等收敛到终态；飞行包等瞬态动画只在 live 播放时产生，重建时跳过。

## 静态图契约（轻量交付时）

1. 手工布局、逐坐标计算，**禁用自动布局**（排版不可控是一切"丑"的根源）。
2. 两世界对照：过程世界与状态世界并置，连线只回答"谁写谁"。
3. 渲染成位图后**亲眼检查再交付**（重叠、穿线、溢出），至少迭代一轮。
4. 配色用经验证的可区分分类色板；文字用墨色不随色走；状态语义色（正常/警告/缺失）必须配文字标签。
5. 载荷与故障场景照录来源，不虚构。

## 工作流程

### 第一步：取证
一手来源优先（协议文档、真实日志、代码）；载荷照录。对每条将写进讲解的关键论断做多源交叉核证（以反驳姿态验证）；出处措辞冲突时以更接近实际行为的为准，并在产物中如实标注分歧，不静默取舍。

### 第二步：抽取模型（四要素）
1. **站点清单**与因果方向（谁向谁推进）。
2. **流动单元**：类型、字段、顺序约束、开/承载/关的生命周期。
3. **状态落点**：被逐步改变的结构——哪些单元写哪个部位、何时定型。
4. **终止机制与故障面**：流程如何宣告结束；哪些单元原子、哪些可部分生效；部分状态长什么样、恢复/回退路径有哪些。

四要素齐了才动工；缺任何一项回第一步补证据。

### 第三步：产出
- 静态图：按静态图契约手工排布。
- 播放器：时间轴引擎 `steps` 数组（id / phase / dur / label / log / focus / state / live）+ `renderTo(i)` 确定性重建 + `next()` 调度 + `setFocus()` 聚光灯。用**组合器工厂**生成重复模式（每类单元一个工厂），禁止手抄长数组。引擎骨架见 [references/engine-skeleton.md](references/engine-skeleton.md)，按当前领域填充，勿改引擎语义。

### 第四步：验证闭环（交付前必过，缺一不交付）
1. 提取 `<script>` 内容跑 `node --check`。
2. 真实浏览器冒烟：DOM 断言 ≥5 个时间点，**必须包含"②在途时状态尚未变化"的反向断言**；故障面板；播放/暂停往返；控制栏坐标恒定断言；无横向溢出；零控制台报错。
3. 关键帧截图逐张目检后才允许交付（静态图同样目检）。
4. 交付用户指定位置（默认桌面），单文件。

## 用户反馈 → 设计规则映射

收到这类反馈直接对应到规则，不要临场发明解法：

| 用户说 | 落到哪条规则 |
|---|---|
| "控件/按钮被推下去了" | 契约 4 —— 固定布局，而不是挪控件 |
| "一步跨过了所有站点" | 契约 2 —— 拆三段子步骤，落效才写入 |
| "看不清当前在哪一步" | 契约 5 —— 聚光灯 |
| "某某过程应该显示出来" | 先查证据：来源里存在则补渲染；是产品层选择则照实呈现并注明 |
| "换个位置 / 好看一点" | 调整视觉层级前先确认不违反 4（布局稳定）与 10（确定性回放） |
| "太丑了" | 手工布局 + 目检迭代，别换自动布局工具 |

## 纪律

- 领域事实不进本文件：skill 只含方法与契约，每次任务重新取证。
- 产出是讲解物，不是被讲解系统的实现参考；不要把演示值当成事实来源。
- 任何与本契约冲突的"更省事"做法，先在回复里说明冲突再行动。
